# 参考案例：强化学习入门成品审计

这份记录来自对 `E:\ppt测试\reinforcement_learning_intro_presentation_demo.pptx` 的复核。它不是要求所有主题都复制同一套版式，而是把一个真实成品中容易被“溢出测试通过”掩盖的问题，转化成可复用的二次精修规则。

## 审计方法

- 读取 PPTX 包和页面几何，确认 15 页、16:9、页面尺寸约为 13.333 × 7.5 英寸。
- 使用 Presentations 提供的渲染工具输出 15 张 PNG，并查看整套 montage 以及单页大图。
- 做对象级统计：463 个 auto shape、43 个 connector/line、1 个原生表格、1 个原生图表、0 个 group、0 个图片。
- 扫描字体和文本：显式使用 Arial 与 Microsoft YaHei，同时保留 Calibri/Calibri Light 主题默认；约 277 个文本 run 小于 18 pt。
- 人工聚焦出 42 个核心公式样文本对象；启发式脚本还会把带 `=` 的概率/价值标签计入。PPTX XML 中没有 `m:oMath` 或 `m:oMathPara`，说明公式是普通文本而不是 Office Math 对象。
- `slides_test.py` 的结构性溢出检查通过；这只能说明没有明显越界，不能证明语义分组、公式规范、层级、图表说明或可编辑性达到要求。

## 主要问题与解决方案

| 类别 | 可观察证据 | 根因 | 新 skill 的修复规则 |
| --- | --- | --- | --- |
| 字体系统 | Arial、Microsoft YaHei、Calibri 主题默认并存；大小分布从 8.2 pt 到 52.5 pt，层级不连续 | 没有显式字体令牌和最小字号门槛 | 先解析并锁定字体；最多两种主字体；正文 18 pt 起，标题、标签、脚注和公式各自有明确档位 |
| 数学公式 | 42 个公式样文本；没有 Office Math；`Vπ(s)`、`Qπ(s,a)`、`V*`、`γ`、`Gₜ` 的字形和上下标依赖普通文本/Unicode | 公式被当作普通标签处理，且没有单一数学语法 | 采用 canonical notation；一条公式一个独立对象；优先 Office Math，否则使用宽度可控的数学文本 fallback，并显式做基线/上下标和单行 fit 检查 |
| 漂浮碎片 | 第 4 页的大号淡色 `5`、`个词 / = 1 个闭环`、`Aₜ ~ π(·|Sₜ)`、右下角说明互相缺少明确指向 | 每个概念都被单独做成文本框，缺乏 owner 和阅读路径 | 每个标签必须拥有一个节点、箭头或区域；无 owner 的标签删除；复杂图最多三个阅读层级 |
| 公式换行 | 多页公式放在窄卡片中，可能被挤压或在渲染时出现不期望的断行 | 没有按最长公式预留宽度，也没有导出后的文本 fit 回查 | 公式区域先量宽，再定字号；设置固定高度和单行宽度；不靠 shrinkText 掩盖问题；逐页回看最长标题/公式 |
| 版式重复 | 15 页几乎机械地深浅交替，并反复使用“kicker + 标题 + subtitle + 卡片 + footer + folio” | 背景切换被当作变化，内容结构却没有变化 | 以语义角色选 layout；连续页面不能复用同一卡片网格；深浅页只在章节转场或语义需要时切换 |
| 卡片过多 | 第 3、6、7、9、10、11、12、14 页均是多卡片拼接；卡片之间没有明显的主次 | 把每个概念都做成独立 UI 面板，主张被切碎 | 优先一个大构图；卡片仅包住真正的概念单元；一页一个 visual anchor，其他信息围绕它服务 |
| 图表说明 | 第 13 页有原生图表，这是优点；但“Method profile”与矩阵、评分尺度、概念性数据的关系不够直观 | 图表虽可编辑，但缺少标题、单位、数据性质和阅读指令 | 使用原生图表；标题说明指标，轴和图例说明量纲；显式加 `Conceptual illustration`；不要在图表外重复大量标签 |
| 关系线 | 第 4、5、9、15 页有多条线、箭头和节点，但线型语义、层级和路由不总是清晰 | connector、节点、标签没有按逻辑分组，线路穿过文本区 | 线型只表达少数固定关系；connector 在节点下方；标签贴近箭头；按逻辑单元 group；避免交叉和悬空线 |
| 图标与装饰 | 多个 pill、badge、靶心/箭头等小图形与正文大小关系不稳定 | 图标是装饰补丁，没有统一尺寸和语义 owner | 使用有限图标集；统一描边和基线；图标只在能降低认知成本时出现 |
| 空间利用 | 第 5、6、8、10、11、12 页部分区域留白较大，而另一处堆叠小标签 | 先放组件再补文字，没有做整体构图和节奏校验 | 先定主视觉占地，再安排支持信息；用大图、时间轴或关系图承载空白，不用更多微文本填缝 |
| 可编辑组织 | 463 个 shape 但 0 个 group，复杂图只能逐个对象寻找 | 对象扁平化，缺少编辑语义 | 对 diagram 做逻辑分组；节点、标签、路径可单独调整；表格/图表/公式保持独立；不把整页 rasterize |
| 文案风格 | 标题和副标题使用引号、箭头和口号式短句，部分信息更像 UI 标签而非演讲主张 | 为了填版面增加了不必要的文本层 | 标题直接说清本页要点；副标题只在提供上下文时保留；箭头只留在图中，不作为 prose 装饰 |

## 逐页重点

- 第 1 页：视觉冲击力尚可，但封面出现 `EDITABLE POWERPOINT DEMO`、大号淡色 `01` 和多组微标签，削弱了“入门主题”的单一主视觉。改为一个明确的 Agent–Environment–Reward 闭环，保留少量副标题。
- 第 2 页：迷宫场景与交互循环并列，两个重卡片争夺注意力。应让场景成为主图，循环作为一条清晰路径叠加或围绕场景布局。
- 第 3 页：左右对比逻辑正确，但普通文本、卡片和原生表格同时抢层级。保留对比轴，减少重复解释，把差异浓缩为四个可扫描维度。
- 第 4 页：最典型的漂浮碎片页。把 State、Action、Reward、Policy、Return 收束成围绕 Agent 的有向关系图，并删除没有指向对象的淡色大字。
- 第 5 页：MDP 状态图概念正确，概率和 reward 标签偏小且散落。应把 action、transition probability、reward 做成统一的边标签，公式放入一个明确的模型定义区。
- 第 6 页：时间轴有价值，但卡片、`EXPLOIT`、`EXPLORE`、`IMMEDIATE` 等 pill 太多。用一条折扣时间轴加一个 policy callout 足够表达。
- 第 7–9 页：Value、Bellman expectation、Bellman optimality 的知识链条存在，但每页都像独立 dashboard。应让“状态好不好”到“递归估计”再到“评估–改进循环”形成逐步升级的视觉节奏。
- 第 10 页：Model-based 与 Model-free 的概念对比正确，但“地图 vs 雾”与公式之间的连接弱。用同一环境上的两条决策路径，让模型、planning、直接学 Q/V 的关系更具体。
- 第 11–12 页：MC 与 TD 的差异被做成两种卡片，但 episode 完整回放与一步 bootstrap 的时间关系不够强。应分别使用“完整轨迹回溯”和“单步 target pipeline”作为主构图。
- 第 13 页：原生 chart 是可保留的能力示范。必须补充 `Conceptual illustration`、指标解释和矩阵到 chart 的映射，减少无关装饰。
- 第 14 页：Sarsa/Q-learning 的公式和 Cliff Walking 直觉都在，但两条算法路径与公式没有共享坐标系。用同一条 S→A→R→S′→A′/max A′ 路径对齐差异。
- 第 15 页：总结地图有视觉高潮潜力，但分支标签和脚注偏小。将主线放大，分支归入三层：模型、学习方式、控制方式；把细节放到 speaker notes。

## 结论

原稿的问题不是“没有图形”，而是图形过多却没有被同一条阅读路径组织。新 skill 应优先执行：内容收束 → 字体/公式规范化 → 语义分组 → 版式角色化 → 原生对象保留 → 渲染后验收。
